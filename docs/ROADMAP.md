## 迭代 1：卡纸 Boss 战（回应试玩 #1）

试玩 #1 反馈：单局约 1 分钟，「按完三个按钮什么都没发生」，玩家期待一场和打印机的战斗。原则：以原 MVP 为基线增量修改——保留离线 → 队列 → 卡纸 → 结算流程、耐心 3、完美／普通／失败规则和「耐心归零优先判负」，协议 v0.1 文件仍可加载。

- [x] 协议 v0.2（向后兼容的增量字段）：行动 `feedback`、行动 `skill`（`timing`／`mash`，失败走 `onFail` 的消耗与目标）、阶段 `intensity`。v0.2 字段出现在 v0.1 文件中会被拒绝；原 v0.1 关卡作为测试夹具保留并通过全部兼容测试。
- [x] 卡纸扩展为 3 个 Boss 回合（盖板 → 拔河 → 最后两厘米），沿用现有阶段机制；每回合一个技巧行动和一个必定扣耐心的蛮力行动。
- [x] 技巧小游戏：时机判定（指针进入绿区时按下）与连打判定（3 秒内 10 次）；以 `performance.now()` 时间戳计时，不依赖帧率；引擎只接收「成功／失败」结果。
- [x] 战斗演出：Boss 血条（由 Boss 回合进度推导，仅用于表现）、「BOSS 出现」标题卡、扣耐心时的反击（3D 纸张飞向镜头／简化显示同样有、震屏、浮动「−1 耐心」）、每回合打印机损伤递增、胜利打印纸。
- [x] 辅助模式：技巧判定自动成功（界面开关或 `?assist=1`）；减少动态效果时指针变慢。
- [x] 测试：Vitest 101 项（含 v0.1 兼容、技巧分支、失败优先、纯函数小游戏规则）；Playwright 36 项（用 Playwright 时钟精确测试两种小游戏）。
- [x] 试玩 #2（作者转述，见 [PLAYTEST.md](PLAYTEST.md)）：大多数人不到 3 分钟通关，认为不需要技巧——「按空格填满进度条」就能赢。由迭代 2 回应。

不在本迭代范围：音效、第二个 Boss、结局分享、随机性、独立的 HP／回合引擎、更多耐心格。（后三项在迭代 2 中因试玩 #2 的反馈而加入。）

## 迭代 2：实时战斗（回应试玩 #2）

试玩 #2 反馈：作为动作游戏，应该要求玩家用特定技能打败 Boss，而不是按空格填满进度条。原则：规则引擎仍是纯函数、仍只看结果；新玩法作为协议的增量扩展，旧关卡照常加载。

- [x] 协议 v0.3（向后兼容）：阶段可声明 `fight: { id, target, feedback? }` 代替 `actions`；`id` 必须是已登记的战斗。引擎新增 `HIT`（扣 1 耐心，归零判负）与 `FIGHT_WON`（走 `target`）。v0.2 关卡（含原来的菜单式打印机关卡，现为测试夹具）照常加载。
- [x] 纯函数实时战斗模拟（`src/game/fight.ts`）：固定 10 ms 子步、带种子的随机数，种子加输入可完全复现。三条通道；四种招式各有预警，各有唯一的应对技能：纸（闪避）、墨粉（按住格挡，格挡时不能移动）、弱点（在对应通道拽出，乱拽会被夹手 0.6 秒）、更新充能（按住重启 0.7 秒打断，否则回血；打断后露出大弱点）。被击中后有 1 秒无敌。
- [x] 关卡：离线、队列两场热身战各教两个技能；卡纸 Boss 战 12 血、三个形态逐步叠加招式。初始耐心 5。
- [x] 战斗界面：通道、预警、纸张飞行、弱点倒计时、墨粉、充能条、形态横幅、开战前的技能说明、暂停（Esc／失焦）、触屏按钮、手机上战斗时缩小 3D 区域并显示紧凑血条；结算显示被击中次数。辅助模式改为战斗放慢到 65%。
- [x] 平衡测试（Vitest，脚本玩家，20 个种子）：反应 350 ms 零失误通关所有战斗；站着不动、狂按拽出、一直格挡、乱按所有键都会耗尽耐心；反应 900 ms 打不过 Boss；零失误 Boss 战约 1 分钟。
- [x] 浏览器测试（Playwright 38 项）：页面内脚本玩家在假时钟下逐帧打完整局，覆盖三种结局、各技能、暂停、触屏、3D／简化显示与手机视口。
- [x] 试玩 #3（作者转述，见 [PLAYTEST.md](PLAYTEST.md)）：墨粉特效不够、动画整体太简单、Boss 最终形态回血太快难以通关。由迭代 3 回应。

不在本迭代范围：音效、第二个 Boss、结局分享、更多攻击种类、难度选择。

## 迭代 3：战斗演出与最终形态难度（回应试玩 #3）

试玩 #3 反馈：墨粉喷射缺少视觉效果；动画整体太简单；Boss 最终形态回血太快，极难通关。原则：特效只读取战斗状态与事件，不影响规则；数值改动用平衡测试验证。

- [x] 粒子特效层（`src/ui/fightEffects.ts` + `FightFxLayer.tsx`，canvas 2D）：墨粉预警漏粉、喷射爆发与墨粉云（落地后向两侧扩散）、CMYK 墨点、被喷中时的墨渍与滴落、格挡时墨粉从护盾弹开；纸张拖尾与落地碎纸；拽出火花与伤害数字；打断冲击波；回血、形态切换与胜利彩纸。粒子数量有上限，绘制超时会自动减少发射量。减少动态效果时不显示；`?fx=0` 可关闭（供快进的浏览器测试使用）。
- [x] 界面动画：震屏与全屏闪光、出纸口发光抖动、落点准星、纸张透视飞行、弱点弹出、护盾罩、闪避残影与形变、形态横幅砸入、胜利停顿约 1.1 秒、Boss 血条拖尾与受伤／回血闪烁、当前该用的技能按钮高亮；3D 打印机被打中时后仰、眼睛闪光。
- [x] 最终形态平衡：更新 7 秒回 1 血（原 5 秒回 2 血），回血不超过该形态起始血量（`fight.ts` 新规则）；更新开始后 0.9 秒空档；每轮两次卡纸。新增平衡测试：从不打断更新的玩家也能获胜且血量不回升，但比打断更新慢。
- [x] 测试：Vitest 新增特效引擎测试与上述平衡测试；Playwright 新增 `e2e/effects.spec.ts`（特效层覆盖战斗区域、不拦截输入、墨粉喷射时覆盖大部分区域；减少动态效果与 `?fx=0` 时不出现）。
- [x] 试玩 #4（作者转述，见 [PLAYTEST.md](PLAYTEST.md)）：大家觉得好玩，没有再提特效或难度问题；新反馈是缺少进入游戏的过程、背景太素。由迭代 4 回应。手机上的帧率（特效层在真机上的性能）仍未测。

## 迭代 4：标题画面、开场剧情与场景背景（回应试玩 #4）

试玩 #4 反馈：一进来就直接开打，没有引导或进入游戏的过程，体验单一；背景太素，像廉价网页游戏。原则：关卡专属文案写在 JSON 里；背景只是装饰，不影响规则与可访问性。

- [x] 标题画面（`src/ui/TitleScreen.tsx`）：游戏名、今日副本、Boss 立绘、一句话简介、目标与耐心、三个阶段的路线（Boss 战标红）、开始游戏（Enter）与辅助模式。标题显示时游戏窗口已挂载但 `inert`，3D 场景提前加载；快捷键（R、数字键）不生效。
- [x] 开场剧情（`src/ui/IntroSequence.tsx`）：逐字打出、带插画的若干段文字，点击／Enter／空格／→ 继续（还在打字时先补全整句），Esc 或「跳过」直接进入战斗；读屏软件始终读到整句；减少动态效果时整句直接出现。结束后焦点落到「开始战斗」。重开不再经过标题和剧情。
- [x] 协议 v0.4（向后兼容）：关卡可选 `intro: { tagline, beats: [{ text, art? }] }`，1–6 段，`art` 取 `clock | document | error | eyes`。打印机关卡升级到 v0.4。
- [x] 场景背景（`src/ui/Backdrop.tsx` + `src/styles/backdrop.css`）：一整张内联 SVG 的深夜房间；灯光随强度和结局切换（平静 → 琥珀 → 警报红 → 天亮／变灰），全部是 CSS。房间完全静止、没有过渡（全屏动画层在软件渲染下会让帧率掉三分之一以上）。游戏窗口浮在房间前，只用描边、不用模糊阴影：窗口每次被打中都会震动并重绘图层，大范围模糊阴影和光晕（以及 `.device` 上的聚光渐变）在无头 Chromium 的软件渲染下会让 GPU 进程积压最多约 30 秒，后续页面创建 WebGL 时卡住，浏览器测试超时。Boss 战时窗口描边变红，通关后变暖色。
- [x] 测试：Vitest 新增 v0.4 `intro` 校验测试；Playwright 新增 `e2e/onboarding.spec.ts`（标题内容与 inert、快捷键关闭、辅助模式带入游戏、剧情逐段推进与焦点、点击推进与 Esc 跳过、重开不回标题、减少动态效果），其余用例通过 `GamePage.open()` 先经过标题与剧情。
- [ ] 试玩 #5：验证开场节奏（是否太长、有没有人跳过）、背景观感，以及手机上的表现。
